gosvc — configuração e uso, passo a passo

Do primeiro build da CLI até uma API Go com PostgreSQL, JWT, observabilidade, Kafka, Outbox, Kubernetes, validação arquitetural, upgrades e certificação.

Começar agoraComparar presetsComandos

1. Visão geral

gosvc é um gerador opinativo para serviços Go. Ele gera código Go comum: o serviço criado não depende do gosvc em runtime.

gosvc CLI→templates + preset→projeto Go→seu código→build/deploy independente

Clean Architecture

Domínio e aplicação ficam protegidos de Chi, pgx, Kafka, JWT e detalhes de infraestrutura.

Geração segura

Ownership, checksums SHA-256, dry-run, escrita atômica e regeneração idempotente.

Pronto para crescer

Presets progressivos: mínimo, PostgreSQL, produção e arquitetura orientada a eventos.

Quality gates

Testes, cobertura, race detector, vet, lint, govulncheck, acceptance e certificação E2E.

Objetivo desta páginaSe você nunca usou o projeto, siga as seções na ordem. Se já conhece o fluxo, use a navegação lateral como referência.

3. Instalação do gosvc

Baixe ou extraia o código-fonte

Entre no diretório do repositório da CLI.

cd gosvc

Valide a própria CLI

make tidy
make verify

Compile

make build VERSION=1.1.0

O binário será criado em bin/gosvc.

Confirme a instalação

./bin/gosvc version
./bin/gosvc --help

Opcional: coloque no PATH

install -m 0755 ./bin/gosvc ~/.local/bin/gosvc
export PATH="$HOME/.local/bin:$PATH"

Quando houver uma release pública

O projeto já gera installer, Homebrew Formula, Scoop manifest e suporta go install.

# Go install
go install github.com/ailtonmacedo/gosvc/cmd/gosvc@v1.1.0

# Shell completion
gosvc completion bash > ~/.local/share/bash-completion/completions/gosvc

4. Escolha o preset

PresetIncluiUse quando
minimal-apiChi, config, health, Docker, testes, cobertura, lint e CIServiço HTTP pequeno, sem banco.
postgres-apiminimal + pgxpool, migrations, sqlc, OpenAPI, validação e ReDocAPI CRUD com PostgreSQL.
production-apipostgres + JWT, refresh token, RBAC, rate limit, slog, Prometheus, OTel, pprofAPI pronta para ambientes produtivos.
event-driven-apiproduction + Redis, Kafka, Outbox, idempotência, DLQ, worker e KubernetesSistemas distribuídos e integração assíncrona.
Regra práticaComece pelo menor preset que resolve o problema. Você evita complexidade operacional desnecessária.

5. Quick start: primeira API

Exemplo recomendado para aprender: uma API PostgreSQL.

Crie o projeto

gosvc new catalog-service \
  --module github.com/acme/catalog-service \
  --preset postgres-api

Entre no diretório

cd catalog-service

Suba o PostgreSQL

docker compose up -d postgres

Configure o banco

export DATABASE_URL='postgres://postgres:postgres@localhost:5432/catalog-service?sslmode=disable'

Instale ferramentas do projeto

make tools

Prepare o schema e gere código

make migrate-up
make generate

Valide e execute

make verify
make run

Teste a API

curl http://localhost:8080/health/live
curl http://localhost:8080/health/ready

7. Entendendo o project.yaml

O project.yaml descreve como o projeto é gerado. Ele não substitui as variáveis de ambiente de runtime.

schema_version: 1

project:
  name: catalog-service
  module: github.com/acme/catalog-service
  go_version: 1.25
  preset: production-api

architecture:
  type: clean
  layout: layered

api:
  enabled: true
  router: chi
  port: 8080
  read_timeout: 10s
  write_timeout: 15s
  idle_timeout: 60s
  shutdown_timeout: 10s
  max_body_size: 1048576

openapi:
  enabled: true
  source: api/openapi.yaml
  strict_server: true
  request_validation: true
  documentation: redoc

database:
  enabled: true
  engine: postgres
  driver: pgx
  pool: pgxpool
  migrations: golang-migrate
  code_generation: sqlc

auth:
  enabled: true
  strategy: jwt
  access_token:
    ttl: 15m
    algorithm: HS256
    issuer: catalog-service
    audience: catalog-service-api
    revocation: none
  refresh_token:
    ttl: 168h
    storage: postgres
    rotation: true
    reuse_detection: true
    transport: http_only_cookie
  rbac: true
  mfa: false

quality:
  coverage:
    minimum: 80

Como validar

gosvc validate-config --print ./project.yaml
Parser YAML intencionalmente restritoO parser embutido aceita mappings aninhados e escalares. Listas, anchors, aliases, tags, chaves duplicadas e valores multiline são rejeitados.

11. Adicionando um CRUD

Use gosvc add resource em presets com banco.

gosvc add resource product \
  --fields 'id:uuid,name:string,price:decimal,active:bool,released_at:datetime' \
  --crud \
  --project ./catalog-service

Tipos suportados

uuidstringint64integerdecimalbooldatetime

decimal atualmente vira int64Para dinheiro, use uma unidade menor explícita (por exemplo, centavos) ou defina uma convenção clara para evitar interpretação como ponto flutuante.

O campo id é obrigatório e deve ser int64 ou uuid.

O que é gerado

  • Entidade e erros de domínio
  • Port de repository
  • Casos de uso + testes
  • Adapter PostgreSQL
  • Queries SQL + snapshot sqlc
  • Migration up/down
  • Handlers HTTP + testes
  • Teste de integração
  • Paths e schemas OpenAPI

Exemplo com postgres-api (rotas públicas)

curl -X POST http://localhost:8080/products \
  -H 'Content-Type: application/json' \
  -d '{
    "name":"Keyboard",
    "price":19990,
    "active":true,
    "released_at":"2026-08-10T12:00:00Z"
  }'

curl http://localhost:8080/products

Depois de adicionar um recurso que altera SQL/OpenAPI:

make migrate-up
make generate
make verify

12. Usando production-api

Crie o projeto

gosvc new catalog-service \
  --module github.com/acme/catalog-service \
  --preset production-api
cd catalog-service

Suba dependências

docker compose up -d postgres prometheus otel-collector

Exporte configuração crítica

export DATABASE_URL='postgres://postgres:postgres@localhost:5432/catalog-service?sslmode=disable'
export JWT_SECRET="$(openssl rand -base64 48)"
export AUTH_COOKIE_SECURE=false

Prepare o projeto

make tools
make migrate-up
make generate
make verify

Crie o primeiro usuário administrador

PASSWORD_HASH="$(go run ./cmd/hash-password 'change-this-password')"

docker compose exec -T postgres psql \
  -U postgres \
  -d catalog-service \
  -v password_hash="$PASSWORD_HASH" <<'SQL'
INSERT INTO users (id, email, password_hash, roles)
VALUES (
  '00000000-0000-4000-8000-000000000001',
  'admin@example.com',
  :'password_hash',
  ARRAY['admin']
)
ON CONFLICT (email) DO NOTHING;
SQL

Execute a API

make run

Login

curl -i -c cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"change-this-password"}' \
  http://localhost:8080/auth/login

A resposta retorna o access token; o refresh token é gravado em cookie HttpOnly com SameSite=Strict.

Usar rota protegida

ACCESS_TOKEN='cole-o-access-token-aqui'

curl http://localhost:8080/orders \
  -H "Authorization: Bearer $ACCESS_TOKEN"

curl http://localhost:8080/admin/ping \
  -H "Authorization: Bearer $ACCESS_TOKEN"

Refresh e logout

curl -i -b cookies.txt -c cookies.txt -X POST \
  http://localhost:8080/auth/refresh

curl -i -b cookies.txt -c cookies.txt -X POST \
  http://localhost:8080/auth/logout
ProduçãoUse HTTPS e defina AUTH_COOKIE_SECURE=true. Não reutilize o secret de desenvolvimento do Compose.

17. Diagnósticos do gosvc

gosvc validate --project ./catalog-service
gosvc check architecture --project ./catalog-service
gosvc doctor --project ./catalog-service
gosvc verify --project ./catalog-service --static

validate

  • Consistência entre project.yaml e go.mod
  • Schema/preset/features do manifest
  • Arquivos ausentes ou modificados
  • Checksums de arquivos gerados
  • Resource registry e migrations estáveis
  • Paths OpenAPI esperados
  • Fronteiras da Clean Architecture

doctor

Procura primeiro ferramentas no ./bin do projeto e depois no PATH.

verify

Com --static, executa somente validação estrutural. Sem essa flag, também executa testes, race, vet, build, lint e vulnerabilidades.

18. Regeneração segura

SituaçãoAção
Arquivo igual ao esperadoSKIP
Arquivo user modificadoPROTECT — preservado.
Arquivo generated modificadoConflito — operação interrompida.
Recuperar generated explicitamenteUse --force.
Mesma definição de resource novamenteNenhuma mudança.

Antes de criar/regenerar, use dry-run:

gosvc new catalog-service \
  --module github.com/acme/catalog-service \
  --preset production-api \
  --dry-run
AtomicidadeO gerador monta e valida o plano antes de ativar a nova árvore, reduzindo risco de projeto parcialmente atualizado.

19. Upgrade, backup e rollback

Veja as notas

gosvc upgrade notes --from 1.0.0 --to 1.1.0

Simule

gosvc upgrade --project ./catalog-service --to 1.1.0 --dry-run

Aplique

gosvc upgrade --project ./catalog-service --to 1.1.0

Por padrão, um ZIP é criado em .gosvc/backups/.

Liste backups

gosvc upgrade backups --project ./catalog-service

Simule rollback

gosvc upgrade rollback \
  --project ./catalog-service \
  --backup latest \
  --dry-run

Restaure

gosvc upgrade rollback \
  --project ./catalog-service \
  --backup latest
Rollback é snapshot completoEle restaura inclusive arquivos do usuário. Faça commit ou stash antes.

20. Plugins externos

Plugins ficam em .gosvc/plugins/<nome>/ e são executados como processos filhos por um protocolo JSON versionado.

gosvc plugins list --project .
gosvc plugins validate --project .
gosvc plugins checksum .gosvc/plugins/audit/bin/audit
gosvc plugins run audit --project . --dry-run
gosvc plugins run audit --project . --timeout 10s

Modelo de segurança

  • Manifest validado
  • Checksum SHA-256 do executável
  • Symlinks rejeitados
  • Timeout e limite de saída
  • Plugin recebe snapshot temporário, não o projeto real
  • Somente artefatos declarados na resposta podem ser aplicados
Não é sandbox de sistema operacionalO executável continua rodando como o usuário atual. Execute apenas plugins confiáveis.

21. Acceptance e certificação

Acceptance offline

gosvc acceptance
gosvc acceptance --json > acceptance-report.json

Gera os quatro presets, adiciona um resource representativo nos presets com banco, valida arquitetura, artefatos e idempotência.

Certificação estática

gosvc certify --mode static

Certificação real E2E

gosvc certify --mode real --require-real
StatusSignificado
PASSExecutou e passou.
FAILExecutou e falhou.
BLOCKEDInfra necessária não existe; não é confundido com aprovação.
SKIPPEDNão aplicável ou omitido por política.

O modo real exercita Go/toolchain, Docker, migrations, PostgreSQL, HTTP CRUD, auth, Redis, Kafka, Outbox e ferramentas de segurança conforme o preset.

23. Problemas comuns

DATABASE_URL is required

O preset com banco está ativo e a variável não foi exportada. Defina DATABASE_URL antes de make run.

JWT_SECRET must contain at least 32 bytes

Gere um secret forte: openssl rand -base64 48.

Copiei .env, mas não funcionou

O app não carrega dotenv. Use set -a; . ./.env; set +a, variáveis da IDE, ou Compose.

Arquivo generated modificado

Use gosvc validate para identificar. Regenere; use --force somente se realmente quiser restaurar o artefato gerenciado.

Go incompatível

Presets com PostgreSQL requerem Go 1.25+ na linha atual. Rode gosvc doctor.

/docs sem interface

O ReDoc visual pode precisar acessar o bundle configurado. O contrato bruto segue disponível em /openapi.yaml.

Kafka funciona no container, não no host

No host use 127.0.0.1:9092; entre containers, kafka:29092.

BLOCKED na certificação

Não é aprovação nem falha funcional. Significa que a infraestrutura/toolchain necessária não estava disponível para executar o check.
