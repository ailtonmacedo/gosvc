# External plugin protocol

`gosvc` v1 executes external plugins through a versioned JSON protocol. Plugins
are discovered inside a generated project:

```text
.gosvc/plugins/<plugin-name>/
├── plugin.json
└── bin/
    └── <entrypoint>
```

External code is never loaded into the `gosvc` process. The executable runs as
a child process with JSON on stdin and stdout.

## Security model

Before execution, `gosvc`:

1. validates the plugin manifest strictly;
2. verifies the entrypoint is a regular executable file and not a symlink;
3. verifies its SHA-256 checksum;
4. copies the plugin into a temporary workspace;
5. copies the project into a separate temporary snapshot;
6. provides a reduced environment;
7. enforces a timeout and a 4 MiB output limit;
8. validates the response and every artifact path;
9. applies accepted artifacts using the normal atomic generator workflow.

The plugin receives the path of the temporary project snapshot, not the real
project. Direct writes to that snapshot are discarded. Only artifacts returned
in the JSON response can reach the real project.

This is **not an operating-system sandbox**. A malicious executable running as
the current user may still inspect resources that the operating system permits.
Only install and execute plugins from trusted sources. Containers, restricted
users, seccomp, or another external sandbox are recommended for hostile code.

## Manifest schema v2

```json
{
  "schema_version": 2,
  "protocol_version": 1,
  "name": "audit",
  "version": "1.0.0",
  "description": "Adds audit artifacts and validation",
  "minimum_gosvc_version": "1.0.0",
  "capabilities": ["artifacts", "validation"],
  "entrypoint": "bin/audit",
  "checksum": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
}
```

Plugin schema v1 remains discoverable as legacy metadata, but cannot be
executed. Upgrade it to schema v2 and add `protocol_version` and `checksum`.

Generate the checksum with:

```bash
gosvc plugins checksum .gosvc/plugins/audit/bin/audit
```

## Capabilities

| Capability | Meaning |
|---|---|
| `validation` | Receives the `validate` action and returns diagnostics |
| `artifacts` | Receives the `contribute` action and returns features and files |
| `commands` | Reserved for a future custom-command protocol |

A plugin may implement validation, artifacts, or both. The `commands`
capability is accepted as metadata but is not executed in protocol v1.

## Commands

```bash
gosvc plugins list --project .
gosvc plugins validate --project .
gosvc plugins checksum .gosvc/plugins/audit/bin/audit
gosvc plugins run audit --project . --dry-run
gosvc plugins run audit --project . --timeout 10s
gosvc validate --project .
```

`plugins validate` verifies manifests, executable permissions, symlink rules,
and checksums. `gosvc validate` additionally verifies installed plugin
references and plugin-produced files recorded in `.gosvc/manifest.json`.

## Request protocol

For each declared capability, the entrypoint receives one JSON document on
stdin. Validation runs before contribution.

```json
{
  "protocol_version": 1,
  "action": "validate",
  "plugin": {
    "name": "audit",
    "version": "1.0.0"
  },
  "project": {
    "root": "/tmp/.gosvc-plugin-123/project",
    "name": "order-service",
    "module": "github.com/acme/order-service",
    "preset": "production-api",
    "features": ["base", "security"],
    "dry_run": true
  }
}
```

The same executable is invoked again with `action: "contribute"` when the
plugin declares `artifacts`.

The environment contains only a small allowlist plus:

```text
GOSVC_PLUGIN_PROTOCOL=1
GOSVC_PLUGIN_ACTION=validate|contribute
GOSVC_PROJECT_DIR=<temporary project snapshot>
```

## Response protocol

```json
{
  "protocol_version": 1,
  "diagnostics": [
    {
      "severity": "info",
      "path": "project.yaml",
      "message": "audit configuration is valid"
    }
  ],
  "contribution": {
    "features": ["trail"],
    "artifacts": [
      {
        "path": "internal/audit/audit.gen.go",
        "content": "// Code generated by audit. DO NOT EDIT.\npackage audit\n",
        "encoding": "plain",
        "mode": 420,
        "ownership": "generated"
      },
      {
        "path": "docs/AUDIT.md",
        "content": "# Audit\n",
        "mode": 420,
        "ownership": "user"
      }
    ]
  }
}
```

`mode` is a JSON number containing Unix permission bits. Decimal `420` is
`0644`; decimal `493` is `0755`.

Binary content may use:

```json
{
  "encoding": "base64",
  "content": "AAECAwQ="
}
```

## Diagnostics

Supported severities:

```text
info
warning
error
```

An `error` diagnostic aborts execution before any project files are changed.
The process must still exit successfully and return valid JSON. A non-zero
process exit code is treated as an execution failure.

## Artifact rules

Plugin artifacts:

- must use clean relative paths with `/` separators;
- cannot target `.gosvc/` or `.git/`;
- cannot collide with core artifacts;
- cannot collide with another plugin's artifacts;
- cannot claim an existing untracked file;
- cannot change ownership of an artifact already registered for that plugin;
- are written only after the complete plan is validated.

A new `user` artifact is created once and protected from later overwrites. A
`generated` artifact may be updated by its producer as long as it was not
manually changed.

Each manifest file record includes an optional `producer` field. Plugin
features are stored with a namespaced value such as:

```text
plugin:audit:trail
```

Core regeneration preserves plugin references, features, and artifacts.

## Minimal shell plugin

```sh
#!/bin/sh
set -eu

read request

case "${GOSVC_PLUGIN_ACTION}" in
  validate)
    printf '%s\n' '{"protocol_version":1,"diagnostics":[{"severity":"info","message":"audit is valid"}]}'
    ;;
  contribute)
    printf '%s\n' '{"protocol_version":1,"contribution":{"features":["trail"],"artifacts":[{"path":"internal/audit/audit.gen.go","content":"package audit\\n","mode":420,"ownership":"generated"}]}}'
    ;;
  *)
    printf '%s\n' "unsupported action" >&2
    exit 2
    ;;
esac
```

## Go plugin entrypoint skeleton

```go
package main

import (
    "encoding/json"
    "fmt"
    "os"
)

type request struct {
    ProtocolVersion int    `json:"protocol_version"`
    Action          string `json:"action"`
}

type response struct {
    ProtocolVersion int `json:"protocol_version"`
    Contribution struct {
        Features []string `json:"features,omitempty"`
    } `json:"contribution,omitempty"`
}

func main() {
    var input request
    if err := json.NewDecoder(os.Stdin).Decode(&input); err != nil {
        fmt.Fprintln(os.Stderr, err)
        os.Exit(1)
    }

    output := response{ProtocolVersion: 1}
    if input.Action == "contribute" {
        output.Contribution.Features = []string{"audit"}
    }

    if err := json.NewEncoder(os.Stdout).Encode(output); err != nil {
        fmt.Fprintln(os.Stderr, err)
        os.Exit(1)
    }
}
```

The machine-readable contracts are available in:

```text
schema/plugin.schema.json
schema/plugin-request.schema.json
schema/plugin-response.schema.json
schema/manifest.schema.json
```
