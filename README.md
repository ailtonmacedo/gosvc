# gosvc

`gosvc` is an opinionated generator for production-oriented Go services. A
project generated by the CLI remains ordinary Go code and has no runtime
dependency on the generator.

## Current status — Sprint 15 / v1.1 real-certification-ready

The repository now generates four presets:

| Preset | Purpose |
|---|---|
| `minimal-api` | Chi, configuration, health checks, Docker, tests, and CI |
| `postgres-api` | Everything in minimal plus pgxpool, migrations, sqlc, OpenAPI, CRUD, and integration tests |
| `production-api` | Everything in postgres plus authentication, RBAC, rate limiting, metrics, tracing, and private pprof |
| `event-driven-api` | Everything in production plus Redis, Kafka, transactional Outbox, a worker process, DLQ handling, and Kubernetes manifests |

The `production-api` preset includes:

- short-lived HS256 JWT access tokens with explicit algorithm, expiration,
  issuer, audience, and clock-leeway validation;
- cryptographically random opaque refresh tokens stored only as SHA-256 hashes;
- refresh-token rotation, reuse detection, session revocation, and logout;
- bcrypt password verification and a password-hash helper command;
- HttpOnly, SameSite=Strict refresh-token cookies;
- authentication middleware and RBAC with an example admin-only route;
- local token-bucket rate limiting by IP or authenticated user, including stale
  entry cleanup;
- structured `slog` request logging with request and trace identifiers;
- Prometheus request metrics at `/metrics`;
- OpenTelemetry OTLP gRPC tracing and a development collector configuration;
- optional pprof on a separate private administration address;
- Prometheus and OpenTelemetry Collector services in Docker Compose;
- generated security, authentication, authorization, rate-limit, logging, and
  metrics tests.

All presets retain deterministic regeneration, file ownership, SHA-256
checksums, architecture validation, an 80% configurable coverage gate,
GolangCI-Lint, govulncheck, and GitHub Actions quality gates.

## Build the generator

```bash
make tidy
make verify
make build VERSION=1.0.0
```

Prepare the definitive repository identity before publishing:

```bash
./bin/gosvc release prepare \
  --repository ailtonmacedo/gosvc \
  --dry-run

./bin/gosvc release prepare \
  --repository ailtonmacedo/gosvc
```



## Run the built-in acceptance matrix

```bash
./bin/gosvc acceptance
./bin/gosvc acceptance --json > acceptance-report.json
```

The matrix generates all four presets, adds a UUID resource to database-backed presets, validates architecture and tracked artifacts, and confirms idempotency. See `docs/ACCEPTANCE.md` and `docs/COMPATIBILITY.md`.

## Release tooling

Generate shell completion:

```bash
./bin/gosvc completion bash > gosvc.bash
./bin/gosvc completion zsh > _gosvc
```

Run the local preflight while the repository still uses its placeholder module:

```bash
./bin/gosvc release check --version 1.0.0 --allow-placeholder
```

Build all release assets:

```bash
SOURCE_DATE_EPOCH="$(git show -s --format=%ct HEAD)" \
  ./bin/gosvc release snapshot \
  --version 1.0.0 \
  --output dist \
  --parallel 3 \
  --allow-placeholder
```

Before publishing, run `gosvc release prepare`, remove `--allow-placeholder`, build the snapshot, and validate it offline:

```bash
./bin/gosvc release verify --dist dist
```

Then follow `docs/RELEASES.md`.

## Generate a production API

```bash
./bin/gosvc new catalog-service \
  --module github.com/acme/catalog-service \
  --preset production-api
```

Then:

```bash
cd catalog-service
cp .env.example .env
docker compose up -d postgres prometheus otel-collector
export DATABASE_URL='postgres://postgres:postgres@localhost:5432/catalog-service?sslmode=disable'
export JWT_SECRET="$(openssl rand -base64 48)"
make tools
make migrate-up
make generate
make verify
make run
```

Database-backed presets currently target Go 1.25 so their generated dependency
set can track the current pgx and OpenTelemetry lines. `minimal-api` continues
to resolve the locally installed Go version.

## Generate an event-driven API

```bash
./bin/gosvc new order-events \
  --module github.com/acme/order-events \
  --preset event-driven-api

cd order-events
cp .env.example .env
docker compose up -d postgres redis kafka prometheus otel-collector worker
export DATABASE_URL='postgres://postgres:postgres@localhost:5432/order-events?sslmode=disable'
export JWT_SECRET="$(openssl rand -base64 48)"
make tools
make migrate-up
make generate
make verify
make run
```

The API and Outbox worker can also run separately:

```bash
make run
make run-worker
```

Kubernetes manifests are written to `deployments/k8s`. They assume PostgreSQL,
Redis, Kafka, and OpenTelemetry are provided by managed services or deployed
separately. Replace image names and create the Secret from the non-applied example before
using the manifests.

```bash
cp deployments/k8s/11-secret.example deployments/k8s/11-secret.yaml
# Edit the copied Secret and replace all placeholders.
make k8s-validate
make k8s-apply
```

## Upgrade an existing project

Preview the migration before writing files:

```bash
./bin/gosvc upgrade --project ./catalog-service --to 1.1.0 --dry-run
```

Apply it after reviewing the plan:

```bash
./bin/gosvc upgrade --project ./catalog-service --to 1.1.0

./bin/gosvc upgrade backups --project ./catalog-service

./bin/gosvc upgrade rollback \
  --project ./catalog-service \
  --backup latest \
  --dry-run

./bin/gosvc upgrade notes --from 1.0.0 --to 1.1.0
```

Legacy schema-v1 and schema-v2 manifests are migrated explicitly to schema v3.
A rollback archive is created before the write, user-owned files remain protected,
managed-file conflicts stop the operation, and the successful transition is
appended to `.gosvc/manifest.json`.

Plugins can be inspected, validated, previewed, and applied explicitly:

```bash
./bin/gosvc plugins list --project ./catalog-service
./bin/gosvc plugins validate --project ./catalog-service
./bin/gosvc plugins checksum ./catalog-service/.gosvc/plugins/audit/bin/audit
./bin/gosvc plugins run audit --project ./catalog-service --dry-run
./bin/gosvc plugins run audit --project ./catalog-service
```

Only plugin response artifacts are applied to the real project. See
`docs/UPGRADES.md`, `docs/BACKUPS.md`, `docs/DEPRECATIONS.md`, `docs/PLUGINS.md`, and the JSON Schemas in `schema/`.

## Create the first development user

```bash
cd catalog-service
PASSWORD_HASH="$(go run ./cmd/hash-password 'change-this-password')"

docker compose exec -T postgres psql \
  -U postgres \
  -d catalog-service \
  -v password_hash="$PASSWORD_HASH" <<'SQL'
INSERT INTO users (id, email, password_hash, roles)
VALUES (
  '00000000-0000-4000-8000-000000000001',
  'admin@example.com',
  :'password_hash',
  ARRAY['admin']
)
ON CONFLICT (email) DO NOTHING;
SQL
```

Login stores the refresh token in a cookie and returns only the access token:

```bash
curl -i -c cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"change-this-password"}' \
  http://localhost:8080/auth/login
```

Refresh and logout:

```bash
curl -i -b cookies.txt -c cookies.txt -X POST http://localhost:8080/auth/refresh
curl -i -b cookies.txt -c cookies.txt -X POST http://localhost:8080/auth/logout
```

Protected routes expect:

```text
Authorization: Bearer <access-token>
```

## Add a CRUD resource

```bash
gosvc add resource product \
  --fields 'id:uuid,name:string,price:decimal,active:bool,released_at:datetime' \
  --crud \
  --project ./catalog-service
```

The command generates domain, ports, use cases, PostgreSQL adapter, sqlc
snapshot, handlers, unit tests, integration test, SQL queries, migrations, and
OpenAPI paths. Migration numbers remain stable in `.gosvc/resources.json`.

Supported field types:

```text
uuid
string
int64
integer
decimal
bool
datetime
```

`integer` and `decimal` currently normalize to `int64`, avoiding implicit
floating-point arithmetic for monetary values. The `id` field is mandatory and
must use `int64` or `uuid`.

## Observability development stack

```text
Application OTLP target: otel-collector:4317
Host OTLP endpoint:       localhost:4317
Prometheus UI:            http://localhost:9090
Metrics endpoint:         http://localhost:8080/metrics
```

The generated collector uses a debug exporter. It demonstrates propagation and
export but does not provide durable trace storage. Attach Tempo, Jaeger, or
another OTLP-compatible backend for retention and querying.

`pprof` is disabled by default. When enabled, it binds to
`127.0.0.1:6060` by default and is not registered on the public API router.

## Project diagnostics

```bash
gosvc validate --project ./catalog-service
gosvc check architecture --project ./catalog-service
gosvc doctor --project ./catalog-service
gosvc verify --project ./catalog-service --static
```

`validate` checks:

- `project.yaml` and `go.mod` consistency;
- manifest schema, preset, and feature composition;
- missing or modified tracked files;
- generated-file checksums;
- resource registry and stable migration files;
- expected OpenAPI paths;
- Clean Architecture import boundaries.

A changed user-owned file produces a warning. A changed generated file is an
error and must be regenerated or explicitly restored.

`doctor` searches project-local tools in `./bin` before `PATH` and reports Go,
Git, Docker, Docker Compose, sqlc, oapi-codegen, golang-migrate,
golangci-lint, and govulncheck.

`verify --static` runs structural validation only. Without `--static`, it also
runs tests, race detection, vet, build, lint, and vulnerability analysis.

## CI policy

Pull Requests execute formatting, module consistency, code-generation checks,
vet, lint, unit tests, coverage, and build. Pushes to `main` additionally run
the race detector, govulncheck, PostgreSQL migrations, integration tests, and a
Docker build.

## Regeneration safety

- unchanged file: `SKIP`;
- modified user-owned file: `PROTECT`;
- modified generated file: conflict;
- explicit generated-file recovery: `--force`;
- repeated resource definition: no changes;
- all writes are staged before the project directory is swapped.

## YAML boundary

The bundled parser supports the subset required by `project.yaml`: nested
mappings and scalar strings, integers, booleans, and durations. Lists, anchors,
aliases, tags, duplicate keys, and multiline values are rejected.
